# 📚 **PART 4 — Knowledge Agent (RAG Search Agent) Full Specification**

Knowledge Agent는 AI-summary에서 “검색·요약·근거 제시” 기능을 담당하는 중심적인 Agent이며,
전체 제품 가치의 50% 이상을 차지한다.

이 Agent는 로컬 문서만 사용하며, Smart Folder 정책 아래에서만 작동한다.
또한 최신 버전에서는 **Chunking v2**, **Grounded Citation**, **Drift-based Re-Embedding**,
**Lock-free Cache** 등 고급 기능을 포함한다.

---

# 1. Knowledge Agent 역할

### 🎯 사용자 관점 기능

* 문서 기반 의미 검색
* 검색된 문서로부터 답변 생성
* 근거(citation) 자동 제시
* 특정 문서 요약 / 문단 요약
* 대화형 질의응답 (Conversation Engine 통합)

### 🎯 기술 관점 목표

* 안정적인 벡터 검색(BGE/E5)
* Chunking 정확도 개선
* Retrieval noise 최소화
* Race condition 없이 캐시 유지
* 문서 변경 시 drift 자동 업데이트

---

# 2. 전체 아키텍처 (현 구현 기준)

Knowledge Agent는 “단일 rag/ 패키지”가 아니라 아래 구성요소의 조합으로 구현되어 있다.

```
core/
  conversation/
    lnp_chat.py                  # 대화/질의/검색+생성 오케스트레이션
  search/
    retriever.py                 # VectorIndex + hybrid(BM25) + atomic cache save
  agents/
    rag/
      citation.py                # [ref: <stem>#<chunk_id>] 인용 규칙 + Sources 보강
  data_pipeline/
    pipeline.py                  # chunking v2(heading-aware) + corpus 생성
  monitor/
    drift_checker.py             # scan_csv/corpus 기반 drift 체크(해시 우선)
scripts/
  run_knowledge_agent.py         # UI 브릿지(JSON 출력) + scope 보강
  pipeline/
    infopilot.py                 # CLI 엔트리포인트(scan/extract/embed/train/chat/watch/drift)
```

Knowledge Agent는 다음 7개 서브시스템으로 구성된다:

1. Chunking v2
2. Embedding Engine
3. Vector Retriever
4. RAG Generation
5. Citation Engine
6. Drift Detector
7. Lock-Free Cache Manager

# 3. End-to-End Flow

```
User Query
   ↓
SmartFolder Policy Check
   ↓
Retriever (vector search)
   ↓
Top-k Chunks
   ↓

   ↓

   ↓

   ↓
UI/CLI 출력
```

모든 검색은 Smart Folder 내부 파일만 대상으로 한다.

# 4. Chunking v2 (`core/data_pipeline/pipeline.py`)

현재 제품에서 가장 개선 여지가 많았던 부분.
Chunking v2는 **semantic, structural, heading-aware** 방식으로 설계한다.

### Chunking 목표

* 의미 경계를 존중
* 문단 단위 chunk
* 길이 균형 유지
* 검색 성능 극대화

### 입력

* 파일 텍스트(str)
* Smart Folder policy (파일 타입, 크기 등)

### Chunking 알고리즘(개념)

1. 문장 단위 split
2. Heading(제목) 검출 (#, ##, 숫자. 형태)
3. Heading 단위로 semantic group 생성
4. 길이 조정:

   * 최소 200 tokens
   * 최대 500 tokens
5. overlap 설정 (30 tokens)

### 출력 형식(개념)

```json
[
  {
    "chunk_id": "f1_c1",
    "file_name": "report.md",
    "heading": "프로젝트 개요",
    "text": "...",
    "embedding": null
  }
]
```

# 5. Embedding Engine (embedder.py)

Embedding은 다음 모델 중 하나를 사용:

* BAAI/bge-m3 (추천)
* intfloat/e5-small (macOS 기본)
* local GGUF embedding 모델도 옵션

### Embedding 기능

* Chunk 리스트 → embedding vector 부여
* Smart Folder policy 기반 접근 확인

# 6. Retriever (`core/search/retriever.py`)

### 검색 알고리즘

1. Query 임베딩 생성
2. Top-k chunk 후보 선택
3. lexical-weight 옵션으로 BM25 혼합
4. Score normalization
5. Final Top-k 반환

### 반환 형식(개념)

```json
{
  "chunks": [
    {
      "chunk_id": "f1_c4",
      "file_name": "report.md",
      "score": 0.85,
      "text": "..."
    }
  ]
}
```

# 7. RAG Generation (Conversation Engine 기반)

### RAG LLM Prompt 구조

```
[User Query]
[Retrieved Chunks]
---
Constraints:
- Answer ONLY using above documents.
- Provide citations in the form `[ref: <stem>#<chunk_id>]`.
```

### Generation Output 예시

```
프로젝트의 핵심 목표는 안정적 의미 검색입니다. [ref: report#12]
```

### LLM 백엔드

* Llama.cpp
* GPT4All
* Qwen 1.5B (옵션)

# 8. Citation Grounding (`core/agents/rag/citation.py`)

Knowledge Agent의 가장 중요한 최소 품질 보장 기능.

### Citation 규칙

* 모든 문장 뒤에 chunk_id 기반 citation 삽입
* citation은 **검색 결과(hits)에 포함된 문서**만 참조할 수 있다(unknown ref 차단).
* ref_id 규칙:

```
<file_stem>#<chunk_id>
예: report#12
```

### Citation 검사

* LLM 응답 분석
* hallucination 여부 판단
* citation이 없거나 unknown ref가 있으면: 응답 끝에 `Sources:` 블록을 자동 부착(최소 신뢰장치)

---

# 9. Drift Detection (`core/monitor/drift_checker.py` + CLI)

검색 안정성과 성능을 위해 반드시 필요한 기능.

### Drift 상태

* 파일 내용 변경
* 파일 삭제
* 파일 추가

### 알고리즘

1. scan_csv/corpus의 file_hash(가능하면) 기반으로 drift 계산
2. mismatch/추가/삭제 발견 시:

   * 해당 파일만 재-scan/재-추출/재-임베딩 대상으로 수집
   * `infopilot.py drift reembed`로 선택 재임베딩 수행

### 출력

```json
{
  "changed": ["report.md"],
  "added": ["newfile.md"],
  "deleted": ["oldfile.md"]
}
```

# 10. Lock-Free Cache Manager (`core/search/retriever.py`)

여러 프로세스가 동시에 캐시를 읽고 쓰는 상황에서 race condition을 줄이기 위해,
인덱스 저장 시 “원자적(atomic) 저장” 전략을 사용한다(메타 파일을 커밋 마커로 사용).

### Lock-free atomic write 방식

1. cache.json.tmp 파일 생성
2. 전체 쓰기 완료 후 rename
3. rename은 원자적 → 경쟁 없음

### 캐시 구성 요소

* chunk_cache.json
* embedding_cache.npy
* scan_state.json

# 11. KnowledgeAgent.run() 전체 흐름

```
def run(query, context):
    validate_policy(context)
    chunks = Retriever.retrieve(query)
    rag_text = RAGGenerator.generate(query, chunks)
    citation_fixed = Citation.fix(rag_text, chunks)
    return citation_fixed
```

# 12. 에러 처리 규칙

| 에러                | 원인                 | 처리          |
| ----------------- | ------------------ | ----------- |
| AccessDeniedError | Smart Folder 경계 위반 | 즉시 종료       |
| NoChunkFoundError | 검색 결과 없음           | “근거 없음” 메시지 |
| EmbeddingError    | 모델 실패              | 재시도 1회      |
| DriftDetected     | 문서 변경              | 자동 인덱스 업데이트 |
| CitationFailure   | hallucination 가능성  | 재생성         |
