# ⚠️ **PART 7 — Unified Error Framework & Logging System**

AI-summary는 Smart Folder 기반 오프라인 AI 도구이므로,
**에러와 로그 체계는 UI/개발자 모두에게 명확하고 일관되게 전달되어야 한다.**

이 문서에서는 Error Hierarchy, Logging Architecture, Audit Log, Telemetry-less Monitoring까지 전부 설계한다.

---

# 1. Unified Error Framework의 목표

### 🎯 기술 목표

* Pipeline / Agents / Conversation Engine / Smart Folder가 **하나의 에러 체계** 사용
* 사용자에게는 단순·명확한 메시지만 노출
* 개발자에게는 풍부한 debugging 정보 제공
* 오프라인 환경에서도 완전한 추적 가능

### 🎯 사용자 가치

* 혼란 없는 에러 메시지
* 해결 방법 제시
* 재시도 가능 여부 명확

---

# 2. Error Hierarchy Overview

전체 에러는 6개 최상위 카테고리로 정의한다.

```
AIError (Base)
 ├── PolicyError
 │     ├── AccessDeniedError
 │     ├── PolicyViolationError
 │
 ├── PipelineError
 │     ├── ScanError
 │     ├── ExtractionError
 │     ├── EmbeddingError
 │     ├── TrainingError
 │     ├── DriftError
 │
 ├── AgentError
 │     ├── STTError
 │     ├── SummarizationError
 │     ├── ActionExtractionError
 │
 ├── ConversationError
 │     ├── PromptError
 │     ├── CitationError
 │     ├── SafetyError
 │
 ├── ModelError
 │     ├── ModelLoadError
 │     ├── ModelInferenceError
 │
 └── SystemError
       ├── FileIOError
       ├── CacheCorruptionError
       ├── UnexpectedRuntimeError
```

# 3. Error Payload Specification

모든 에러는 아래 공통 구조를 가진다.

```
{
  "error_type": "AccessDeniedError",
  "message": "파일에 접근할 수 없습니다.",
  "hint": "Smart Folder 정책을 확인하세요.",
  "context": {
    "path": "/docs/private/secret.pdf"
  },
  "timestamp": "2025-12-08T15:31:00",
  "severity": "medium|high|critical"
}
```

### 필드 설명

* **error_type**: 에러 클래스명
* **message**: 사용자에게 노출되는 짧은 메시지
* **hint**: 해결 방법
* **context**: 디버깅용
* **timestamp**: ISO-8601
* **severity**: 정책 위반, 시스템 오류 등 중요도 표현

---

# 4. User-facing Messages vs Developer-facing Logs

### 사용자 메시지는 단순해야 함

예:

```
"이 파일은 정책에 따라 읽을 수 없습니다."
"오디오 파일을 처리하는 데 문제가 발생했습니다."
"문서 기반 답변을 생성할 수 없습니다."
```

### 개발자용 로그는 상세해야 함

예:

```
AccessDeniedError: SmartFolderContext denied access
path=/docs/secret.pdf
policy=allowed_types=[".md", ".txt"]
```

# 5. Logging Architecture Overview

```
core/
  logging/
    logger.py
    audit.py
    metrics.py
```

로그는 3가지 스트림으로 나뉜다.

1. **runtime log**

   * 개발자 디버깅용
   * pipeline, agents, LLM 전체의 detail log

2. **audit log**

   * 정책 위반, 파일 접근, STT/summary 처리 기록
   * 운영팀이 볼 수 있는 기록

3. **user event log**

   * 사용자가 어떤 기능을 실행했는지
   * UI/CLI 이벤트 중심

---

# 6. Runtime Log Spec

경로:

```
artifacts/logs/runtime/YYYY-MM-DD.log
```

내용:

* pipeline 단계별 상태
* 모델 로딩 시간
* embedding 중 스레드 사용량
* LLM generation latency
* drift detection 결과

예:

```
[2025-12-08 15:40:12] [INFO] Scan started: root=/docs
[2025-12-08 15:40:12] [INFO] 53 files found (allowed=42, denied=11)
[2025-12-08 15:40:12] [ERROR] ExtractionError: failed to parse pdf at /docs/secret.pdf
```

---

# 7. Audit Log Spec (보안 관점 핵심)

Audit Log는 **Smart Folder 정책 위반**, **민감 기능 호출**, **STT 요약 생성**,
**Agent 실행 등** 추적 가능한 활동만 기록한다.

경로:

```
artifacts/logs/audit/YYYY-MM-DD.jsonl
```

한 줄 예시:

```json
{
  "event": "PolicyViolation",
  "path": "/docs/secret.pdf",
  "policy": "deny_types",
  "timestamp": "2025-12-08T15:41:05"
}
```

Audit Log는 변경 금지 append-only 파일이다.
운영팀이 Smart Folder 오용 여부 확인 가능.

# 8. User Event Log Spec

# 9. Telemetry-less Metrics System

AI-summary는 오프라인 기반이므로 외부 서버 전송은 없다.
모든 메트릭은 로컬 파일로만 기록된다.

경로:

```
artifacts/logs/metrics/system.json
```

추가 로그(파이프라인 운영):

```
artifacts/logs/drift_log.jsonl
artifacts/logs/resource_log.jsonl
artifacts/logs/semantic_baseline.json
```

측정 항목:

* 평균 STT 시간
* 평균 요약 생성 시간
* embedding 처리량
* 검색 latency
* drift 발생 빈도

형식:

```json
{
  "avg_stt_seconds": 12.4,
  "avg_rag_latency": 110,
  "avg_embedding_batch": 78
}
```

# 10. Error Routing Rules

### Pipeline 단계별 에러 처리

| 단계      | 에러                | 처리                    |
| ------- | ----------------- | --------------------- |
| scan    | AccessDeniedError | 해당 파일 skip            |
| extract | ExtractionError   | fallback extractor    |
| embed   | EmbeddingError    | re-load model & retry |
| train   | TrainingError     | 중단 후 사용자 메시지          |
| watch   | DriftError        | 자동 재-임베딩              |

---

### Agent 단계별 에러 처리

| 모듈      | 에러                    | 처리                               |
| ------- | --------------------- | -------------------------------- |
| STT     | STTError              | fallback STT (wav2vec → whisper) |
| Summary | SummarizationError    | 요약 재시도                           |
| Action  | ActionExtractionError | 빈 리스트 처리                         |

---

### Conversation 단계별 에러 처리

| 모듈       | 에러              | 처리              |
| -------- | --------------- | --------------- |
| Prompt   | PromptTooLarge  | prompt truncate |
| Citation | NoCitationError | 재생성 시도          |
| Safety   | SafetyError     | 강제 필터링          |

---

# 11. Developer Constraints

✔ Smart Folder를 우회한 파일 접근 금지
✔ raw STT를 로그에 기록 금지
✔ 에러 발생 시 traceback은 runtime log에만 저장
✔ audit log는 append-only
✔ 모든 캐시 write는 atomic rename
✔ 에러 생성 시 반드시 error_type/hint/context 포함
✔ LLM에게 에러 원문 전달 금지 (보안 위험)
