# 💬 **PART 5 — Conversation Engine (LNP Chat) Full Specification**

Conversation Engine(LNP Chat)은 AI-summary에서 사용자가 직접 상호작용하는 “인터페이스 레벨 AI”이며,
Knowledge Agent / Meeting Agent / Photo Agent를 **통합된 대화형 UI**로 묶는 핵심 계층이다.

이 엔진은 다음 5가지 원칙을 따른다:

1. **Smart Folder 기반 접근 제어**
2. **RAG + Local LLM 조합**
3. **대화 메모리 컨텍스트 유지**
4. **정책 기반 마스킹**
5. **Agent Orchestration** (자동 에이전트 호출)

---

# 1. Conversation Engine의 목표

### 🎯 사용자 가치

* 자연어로 질문하면 문서 기반 답변을 제공
* 요약, 정리, 변환, 결론 요청 등 다양한 작업 지원
* 필요한 경우 자동으로 Meeting Agent나 Photo Agent로 전환
* 오프라인에서 빠르게 작동

### 🎯 기술 목표

* RAG 검색 ↔ LLM 생성 결합
* 대화 메모리 안정성
* Smart Folder 기반 정책 준수
* 프롬프트 일관성과 환각 방지

# 2. Conversation Engine 전체 아키텍처 (현 구현 기준)

```

    orchestrator.py

  agents/
    document/

```

Conversation Engine은 다음 7개 서브모듈로 구성된다:

1. Memory System (`core/conversation/prompting.py`의 `MemoryStore`)
2. Prompt Builder (`core/conversation/prompting.py`의 `PromptManager` + `LNPChat._compose_prompt()`)
3. LLM Backend (`core/conversation/llm_client.py`)
4. RAG Bridge (`core/search/retriever.py` + `core/data_pipeline/pipeline.py`)
5. Policy Filter (`core/data_pipeline/policies/engine.py` + `policy_scope`)
6. Safety/Citation (`core/agents/rag/citation.py`)
7. Translation Cache (`core/conversation/translation_cache.py`, `<cache_dir>/translations.sqlite3`)

# 3. End-to-End Flow

```
User Message
    ↓
Memory + History Merge
    ↓
Smart Folder Policy Injection
    ↓
Intent Detection
    ↓
  ┌─────────── Agent Needed? ───────────┐
  │ yes → Meeting/Photo Agent 호출       │
  │ no  → Knowledge RAG or Pure LLM 응답 │
  └──────────────────────────────────────┘
    ↓
LLM 답변 생성
    ↓
Citation / Safety 정리
    ↓
Output to User
```

# 4. Message Memory System (`core/conversation/prompting.py`)

대화 품질의 70% 이상은 Memory System이 결정한다.

### Memory 구조

```
memory = {
  "recent_messages": [...],
  "system_context": "...",
  "smartfolder_context": { ... },
  "agent_context": null
}
```

### Memory 기능

* 최근 메시지 5~10개 유지
* Smart Folder 메타데이터 자동 주입
* Agent 실행 후 결과물을 Memory에 통합

### 규칙

✔ Memory overflow 방지 (최대 token 제한)
✔ Meeting Agent 요약은 Memory에 자동 추가
✔ 민감 정보는 저장 전에 Masking

---

# 5. Prompt Builder (`core/conversation/prompting.py` + `lnp_chat.py`)

Prompt Builder는 LLM에게 전달되는 모든 입력을 규격화한다.

### 기본 프롬프트 구조

```
[System Rules]
[SmartFolder Context]
[Conversation History]
[User Message]
[Retrieval Context (optional)]
---
Produce a grounded answer with citations.
```

### Prompt Builder 책임

* hallucination 방지 지침 포함
* citation 강제 규칙 포함
* 정책 위반 정보 제거
* Agent 전환 표시

---

# 6. LLM Backend Manager (`core/conversation/llm_client.py`)

AI-summary는 오프라인 LLM 환경이므로
LLM Backend는 모든 로컬 모델을 통합 관리한다.

### 지원 모델

* LLaMA.cpp
* GPT4All
* Qwen (GGUF)
* TinyLLaMA
* Vicuna (옵션)

### Backend 책임

* 모델 로딩/언로딩
* inference 파라미터 설정
* 온디맨드 메모리 관리
* fallback 모델 사용

### 백엔드 구조

```python
class LLMBackend:
    def load()
    def generate(prompt)
    def unload()
```

### fallback 규칙

* 모델 실패 시 → 더 작은 모델로 교체
* prompt 길이 초과 → truncated prompt

# 7. RAG Bridge (Conversation Engine 내부)

Conversation Engine은 Knowledge Agent(RAG)를 자동 호출할 수 있다.

### 조건

* 검색이 필요한 질문 → retriever 호출
* Smart Folder 정책 만족 여부 검사

### RAG Bridge 작업

1. Query embedding
2. Retriever 호출
3. Chunk selection
4. Citation-ready context 생성
5. Prompt Builder로 컨텍스트 전달

### RAG 출력

```
{
  "context": "... retrieved text ...",
  "citations": [...],
  "chunks": [...]
}
```

# 8. Policy Filter (Conversation Engine 내부)

대화 전체에 Smart Folder 정책을 주입하는 역할.

### Policy Filter 기능

* 파일 접근 제어

* 마스킹 옵션 적용

### 예: 이메일 출력 금지


# 9. Safety Filter (Citation Grounding)

Safety는 “환각 방지 + Grounding 보장”이 주요 목표

### Safety 검증 로직

* 답변이 문서 기반인지 확인
* citation이 없거나 unknown ref가 있으면 응답 끝에 `Sources:`를 최소한으로 추가해 근거를 남김
* policy 위반(스코프 밖/민감 경로) 히트는 검색 단계에서 제외
* 근거 없는 주장 → 재생성 요청

### 실패 시 처리

* 1차 재생성
* 여전히 실패 → "근거 부족" 메시지 출력

# 10. History Cache (현 구현 기준)

현 구현에서 **대화(turn) 자체는 세션 메모리로만 유지**되며, 별도 파일로 영구 저장하지 않는다.
대신 UI 편의 기능을 위해 “최근 사용 경로” 히스토리만 사용자 홈에 저장한다.

### 저장 경로 (최근 경로 히스토리)

```
`~/.infopilot/agent_history.json` (meeting_audio / photo_roots 최근 N개)
```

### 캐시 규칙

* 최근 100 메세지까지만 저장
* 민감 정보 masking 후 저장

> 현재 구현은 `scripts/pipeline/infopilot_cli/history.py`에서 CLI 히스토리(최근 경로)를 관리하며,
> 대화 히스토리 영구 저장은 향후 확장 포인트입니다.
* Agent 생성 결과 자동 기록

# 11. LNPChat.run() 전체 흐름 (개념)

Complete flow:

```
def run(user_msg, smartfolder):
    memory = Memory.load(smartfolder)
    intent = IntentDetector.detect(user_msg)

    if agent_needed(intent):
        result = AgentManager.run(intent, smartfolder)
        memory.update(result)
        return result

    retrieval = RAGBridge.retrieve_if_needed(user_msg, smartfolder)
    prompt = PromptBuilder.build(user_msg, memory, retrieval, smartfolder)

    raw_output = LLMBackend.generate(prompt)
    filtered = PolicyFilter.apply(raw_output)
    safe_output = SafetyFilter.check(filtered, retrieval)

    memory.append(user_msg, safe_output)
    Memory.save(memory)

    return safe_output
```

# 12. 에러 처리 규칙

| 에러                  | 원인              | 처리               |
| ------------------- | --------------- | ---------------- |
| AccessDeniedError   | Smart Folder 위반 | 즉시 실패            |
| NoModelLoadedError  | LLM 미로딩         | 자동 로딩            |
| PromptTooLargeError | Prompt > limit  | truncation       |
| NoCitationError     | grounding 실패    | 재생성              |
| AgentSwitchError    | Agent 호출 실패     | generic fallback |
