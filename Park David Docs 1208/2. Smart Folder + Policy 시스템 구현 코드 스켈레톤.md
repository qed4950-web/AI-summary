# 📦 **PART 2 — Smart Folder System (Full Specification)**

AI-summary의 **Smart Folder System**은 “데이터 경계”를 만드는 핵심 인프라다.
이 시스템은 **어떤 Agent가 어떤 파일을 읽을 수 있는지**,
**어떤 정책이 적용되는지**,
**어떤 파일은 즉시 차단해야 하는지**,
**어떤 결과물에 마스킹을 적용해야 하는지**를 결정한다.

Smart Folder는 “데이터 레이크”가 아니라
**정책이 붙은 데이터 샌드박스**다.

---

# 1. Smart Folder Design Goals

### 🎯 1) 안전한 데이터 경계 생성

* Agent는 Smart Folder 외부 파일에 절대 접근 불가
* LLaMA·RAG에도 같은 제한 적용
* 사용자 실수로 다른 폴더를 스캔해도 정책이 즉시 차단

### 🎯 2) 정책 기반의 정교한 제어

* 파일 확장자 기준 허용/거부
* 민감 정보 자동 마스킹
* Agent별 접근 허용/금지
* 정책 위반 발생 시 fail-fast

### 🎯 3) 오프라인 환경에서도 단순하고 빠르게

* 단일 registry.json로 관리
* 변경 즉시 반영
* 캐싱 및 해시 기반 drift 검출

### 🎯 4) 모든 에이전트에서 일관성 유지

* Meeting Agent → 오디오, 문서
* Knowledge Agent → 텍스트, PDF
* Photo Agent → 이미지

---

# 2. Smart Folder Structure

Smart Folder는 설정 디렉토리 아래 다음 구조를 가진다:

```
configs/
  smart_folders.json      ← Smart Folder 목록
  policies/
    base_policy.json
    meeting_policy.json
    knowledge_policy.json
    photo_policy.json
```

---

# 3. smart_folders.json Spec (핵심!)

예시:

```json
{
  "folders": [
    {
      "id": "sf_001",
      "name": "Work Documents",
      "path": "/Users/me/Documents/Work",
      "recursive": true,
      "allowed_types": ["txt", "md", "pdf", "docx"],
      "policy": "base_policy.json",
      "agents": ["knowledge", "meeting"]
    }
  ]
}
```

### 필드별 의미

| 필드            | 설명                 |
| ------------- | ------------------ |
| id            | Smart Folder 고유 ID |
| name          | UI 표시 이름           |
| path          | 실제 파일 경로           |
| recursive     | 하위 폴더 포함 여부        |
| allowed_types | 확장자 whitelist      |
| policy        | 적용할 정책 파일 이름       |
| agents        | 어떤 Agent가 접근 가능한지  |

---

# 4. Policy File Spec

### 정책 파일 예:

```json
{
  "deny_types": ["exe", "dll", "zip"],
  "masking": {
    "email": true,
    "phone": true,
    "person_name": false
  },
  "max_file_size_mb": 50,
  "agent_rules": {
    "meeting": {
      "allow_types": ["wav", "mp3", "m4a", "txt", "md"],
      "deny_types": ["pdf"],
      "mask_stt_output": true
    },
    "knowledge": {
      "allow_types": ["txt", "md", "pdf", "docx"],
      "mask_documents": false
    }
  }
}
```

### 정책 구성 요소

| 항목               | 설명           |
| ---------------- | ------------ |
| deny_types       | 전역 차단 확장자    |
| masking          | 개인정보 마스킹 설정  |
| max_file_size_mb | 크기 제한        |
| agent_rules      | 에이전트별 커스텀 정책 |

# 5. Smart Folder Runtime Behavior (실행 시 동작 흐름)

## 단계 1: Smart Folder 로딩

* infopilot.py 시작 시 smart_folders.json 로딩
* 유효하지 않은 경로는 경고 + 제외
* UI에서는 선택 가능한 Smart Folder 목록만 표시

## 단계 2: Agent 호출 시 컨텍스트 삽입

모든 Agent는 다음 시그니처를 가져야 한다:

```python
run(agent_context: SmartFolderContext, ...)
```

SmartFolderContext 구성:

```
root_path  
allowed_types  
policy  
agent_name  
```

## 단계 3: 파일 접근 요청 발생

예:

* RAG 검색 시 문서 로드
* Meeting Agent가 오디오 파일 로드
* Photo Agent가 이미지 로드

→ SmartFolderEngine.check_access() 호출
→ 실패 시 즉시 error raise

## 단계 4: 정책 위반 처리

정책 위반 유형:

| 유형         | 예                      | 처리       |
| ---------- | ---------------------- | -------- |
| 타입 위반      | .zip 파일                | 즉시 차단    |
| 사이즈 초과     | > 50MB                 | 무시 + 경고  |
| 에이전트 허용 X  | Meeting Agent가 .pdf 요청 | 강제 차단    |
| Masking 필요 | STT 텍스트                | 마스킹 후 전달 |

# 6. Smart Folder Engine Internal Modules

이 엔진은 core/smartfolder/ 아래 다음 구성으로 설계된다:

```
smartfolder/
  loader.py
  validator.py
  access_control.py
  masking.py
  context.py
```

### 1) loader.py

* smart_folders.json 읽기
* 경로 유효성 검사
* 정책 파일 병합

### 2) validator.py

* 확장자 검사
* 파일 크기 검사
* Agent별 접근 검사

### 3) access_control.py

* check_access(path, agent) 구현
* 위반 시 AccessDeniedError 발생

### 4) masking.py

* 이메일, 전화번호, 주소 자동 마스킹
* Meeting Agent 전용 마스킹 규칙 포함

### 5) context.py

* SmartFolderContext 객체 생성
* Agent별 실행마다 전달

# 7. CLI User Flow (Smart Folder UI 흐름)

CLI로 Smart Folder를 운영하는 경우 workflow는 다음과 같다.

### 1단계: Smart Folder 선택

```
python infopilot.py run chat
→ Smart Folder 선택 메뉴 표시
```

### 2단계: Agent 선택

```
1) Knowledge Agent
2) Meeting Agent
3) Photo Agent
```

### 3단계: 정책 자동 검사

* 허용되지 않은 폴더 → 경고
* 스마트 폴더 재설정 옵션 표시

### 4단계: Agent 실행

* Agent 내부 모든 파일 접근은 Smart Folder 정책을 반드시 통과해야 함

# 8. Developer Flow (개발자 준수 규칙)

모든 개발자는 다음 규칙을 따라야 한다:

### ✔ 1) 절대 Smart Folder 외부 경로를 코드에서 접근하지 말 것

금지 패턴:

```python
open(os.path.expanduser("~/Documents"))
```

### ✔ 2) 모든 파일 접근 전에 AccessControl.check_access()를 호출할 것

위반 시 PR reject

### ✔ 3) Agent별 파일 허용 규칙을 코드에서 하드코딩 금지

* 반드시 정책 파일 기준
* 하드코딩은 리팩토링 시 제거 대상(dead code)

### ✔ 4) Masking Layer를 거치지 않은 STT 결과를 저장 금지

Meeting Agent strict rule.

### ✔ 5) Smart Folder 변경 시 drift pipeline 재실행 필요

개발 문서에 기록할 것.

# 9. Error Handling Framework

### AccessDeniedError

```
File is not allowed under Smart Folder policy.
```

### PolicyViolationWarning

* 파일은 읽기되지만 일부 mask 처리됨

### SmartFolderMissingError

* registry.json 불일치

### MaskingError

* 정규표현식 실패 → fallback masking 수행

# 11. Smart Folder → Pipeline → Agents 연결 흐름

전체 데이터 System은 다음 순서로 동작한다:

```
Smart Folder 선택
    ↓
Policy 엔진 로딩
    ↓
파일 스캔(scan)
    ↓
추출 → 임베딩 → 학습
    ↓
Agent 실행
    ↓
Policy 기반 결과 마스킹
    ↓
결과물 저장
```

Smart Folder는 **모든 단계의 가장 위에서 경계를 통제**한다.
