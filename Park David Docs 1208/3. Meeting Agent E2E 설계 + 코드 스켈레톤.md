# 🎙️ **PART 3 — Meeting Agent (Full E2E Specification)**

Meeting Agent는 AI-summary에서 가장 복잡하고 “하나로 묶였을 때 가치가 폭발하는” 에이전트다.
단순 요약기가 아니라 아래 **5개 서브시스템이 연결된 완전한 자동화 Agent**다:

1. **STT (음성 → 텍스트)**
2. **Normalization (전처리)**
3. **Summarization (요약)**
4. **Action Item Extraction (액션 아이템)**
5. **Masking Policy (민감 데이터 제거)**
6. **Artifact Storage (결과물 구조화 저장)**

Meeting Agent는 Smart Folder 정책 아래서만 작동하며, 외부 파일은 절대 읽지 않는다.

---

# 1. Meeting Agent 목표

### 🎯 사용자 가치

* 회의 파일을 넣기만 하면 **자동으로 요약·액션 추출·정리**
* 매번 같은 형식의 결과물 생성 → 조직에서 표준화 가능
* 오프라인 작동 → 회사 내부기밀 보호

### 🎯 기술 목표

* Whisper/wav2vec 기반 STT를 안정적으로 수행
* STT → 요약 → 액션 → 마스킹의 **파이프라인형 연결**
* Smart Folder 정책 기반 접근
* 실패 지점은 즉시 fail-fast
* artifacts/<meeting_id>/ 구조로 영구 저장

# 3. E2E Flow Overview (회의 처리 전체 흐름)

```
Audio File
   ↓
STT (음성→텍스트)
   ↓
Normalization (불필요 음절 제거)
   ↓
Summarization (회의 요약)
   ↓
Action Item Extraction
   ↓
Masking Layer
   ↓
Artifact 저장
```

Meeting Agent는 단일 엔트리 함수로 실행된다:

```python
result = MeetingAgent.run(audio_path, smartfolder_context)
```

---

# 4. Step-by-step Details

---

# 4.1 STT Engine (stt_engine.py)

Meeting Agent의 입력은 반드시 Smart Folder 정책에서 허용된 오디오 파일이어야 한다.

### 지원 모델

* wav2vec2 (온전히 오프라인 가능)
* Whisper.cpp (선택)

### 출력 형식

```json
{
  "text": "회의 전체 텍스트 ...",
  "segments": [
    { "start": 0.3, "end": 2.1, "text": "..." },
    { "start": 2.2, "end": 6.0, "text": "..." }
  ],
  "language": "ko"
}
```

### STT 실패 시 처리

* AccessDeniedError (폴더 정책 위반)
* STTModelLoadError
* AudioFormatError
* TooLargeFileError
  → 모두 fail-fast.

---

# 4.2 Normalization Layer (preprocessor.py)

STT 결과에는 다음과 같은 노이즈가 포함될 수 있다:

* 잡음 텍스트 ("음…", "어…")
* 중복 문장
* 헛된 음절
* filler words: "그러니까", "어떤"

Normalization 과정:

* 문장 정제(cleaning)
* 중복 제거(dedup)
* 문장 분리(sentence split)
* 불필요 음절 제거

출력:

```
normalized_text: str
sentences: List[str]
```

---

# 4.3 Summarization Layer (summarizer.py)

### 입력

* normalized_text
* Smart Folder policy (마스킹 여부)

### 모델 옵션

오프라인 환경 대비:

* LLaMA.cpp (recommended)
* Qwen-1.5B-GGUF 가능
* GPT4All 모델도 옵션

### 요약 방식

* extractive + abstractive 혼합
* 요약 토큰 제한 configurable

### 출력

```
summary: str
highlights: [str]
```

---

# 4.4 Action Item Extraction (action_extractor.py)

Action Item은 “실행 가능 문장”을 추출하는 단계다.

LLM + 규칙 기반 혼합 모델:

### 패턴 기반

* "해야 한다"
* "다음 회의까지"
* "담당: 홍길동"
* "마감일: "

### LLM 기반

요약 텍스트로부터 action을 재추출하는 방식.

### 출력

```json
{
  "actions": [
    {
      "task": "다음 스프린트까지 디자인 시안 제작",
      "owner": "홍길동",
      "due": "2025-12-12"
    }
  ]
}
```

---

# 4.5 Masking Layer (masking.py)

Meeting Agent에서 매우 중요한 보안 기능.

### 마스킹 대상

* 이메일
* 전화번호
* 주소
* 주민번호
* 특정 회사명
* 특정 인명 (옵션)

예:

```
"홍길동" → "[PERSON]"
"user@example.com" → "[EMAIL]"
"010-1234-5678" → "[PHONE]"
```

마스킹은 다음 단계에 적용됨:

1. STT raw output
2. normalized output
3. summary
4. action items
5. 저장되는 모든 .txt/.md

정책에 따라 선택적으로 masking 가능.

---

# 4.6 Artifact Storage (artifact_writer.py)

Meeting Agent 결과물은 다음 구조로 저장된다:

```
artifacts/
  meeting/
    2025-12-08_15-30_projectX/
      raw_stt.txt
      normalized.txt
      summary.md
      action_items.json
      metadata.json
```

### metadata.json 예시

```json
{
  "meeting_id": "2025-12-08_15-30_projectX",
  "created_at": "2025-12-08T15:31:00",
  "source_audio": "meeting1.wav",
  "language": "ko",
  "duration": 3600,
  "masking_enabled": true
}
```

# 5. MeetingAgent.run() 최종 흐름

Meeting Agent의 실행은 다음과 같이 구성된다:

```
def run(audio_path, context):
    validate_path_with_policy(audio_path, context)
    stt = STTEngine.transcribe(audio_path)
    stt_masked = Masking.apply(stt)

    norm = Preprocessor.clean(stt_masked.text)

    summary = Summarizer.generate(norm)
    summary_masked = Masking.apply(summary)

    actions = ActionExtractor.extract(summary_masked)

    artifacts = ArtifactWriter.save_all(...)
    return artifacts
```

# 6. 에러 처리 규칙 (Critical)

| 에러                | 시점    | 원인                 | 처리               |
| ----------------- | ----- | ------------------ | ---------------- |
| AccessDeniedError | 시작    | Smart Folder 정책 위반 | 즉시 종료            |
| AudioLoadError    | STT   | 손상된 오디오            | 사용자에 경고          |
| STTFailure        | STT   | 모델 에러              | fallback STT     |
| SummaryFailure    | 요약    | LLM 불안정            | retry 1회         |
| ActionFailure     | 액션 추출 | 입력 비정형             | 빈 리스트 반환         |
| MaskingError      | 마스킹   | regex 실패           | fallback masking |

# 8. 유지보수 규칙 (개발자용)

### ✔ STT raw 텍스트를 마스킹하지 않고 저장 금지

→ 무조건 Masking Layer가 통과해야 함

### ✔ 파일 접근 시 항상 SmartFolderEngine.check_access() 호출

→ 정책 통일성 유지

### ✔ 요약/액션 LLM 프롬프트는 규격화

→ reproducibility 확보

### ✔ artifact 폴더명은 타임스탬프 기반

→ 충돌 방지
