# 🧩 **PART 6 — Smart Folder Integration with Pipeline (scan → extract → embed → train → watch)**

AI-summary의 Pipeline은 다음 5단계로 구성된다:

1. **scan** — 파일 목록 수집
2. **extract** — 텍스트 추출 및 정제
3. **embed** — embedding 생성
4. **train** — topic model / index 생성
5. **watch** — 변경 감지 및 증분 업데이트

Smart Folder는 **이 모든 단계의 상위에서 데이터 경계를 강제**하는 시스템이다.

---

# 1. Smart Folder가 Pipeline에 제공하는 기능

### ✔ 데이터 접근 경계

Pipeline은 Smart Folder 내부 파일만 스캔 가능.

### ✔ 정책 기반 filtering

* 허용 확장자만 처리
* 거부 유형은 즉시 제외
* 파일 크기 제한 적용

### ✔ drift 기반 증분 처리

Smart Folder 변경 시 drift 시스템이 pipeline에 업데이트 신호를 보냄.

### ✔ masking 및 privacy 보장

텍스트 추출 단계에서 기본 masking 가능.

### ✔ Agent 통합

검색 또는 Meeting Agent에서 pipeline 산출물을 직접 사용.

# 2. 전체 Pipeline 아키텍처

```
core/
  data_pipeline/
    scanner.py
    extractor.py
    embedder.py
    trainer.py
    watcher.py

smartfolder/
  loader.py
  validator.py

```

Pipeline은 SmartFolderContext를 다음과 같이 받는다:

```python
Pipeline.run(smartfolder_context)
```

# 3. Integration Overview Diagram

```
Smart Folder Context
        ↓
Pipeline.scan()
        ↓
apply policy.filter()
        ↓
Pipeline.extract()
        ↓
masking / normalization
        ↓
Pipeline.embed()
        ↓
Smart Folder allowed-types 검사
        ↓
Pipeline.train()
        ↓
Pipeline.watch()
```

Smart Folder는 “패스스루(pass-through)”가 아니라
**Pipeline 전체의 gatekeeper + policy enforcer**이다.

# 4. Step-by-step Integration Spec

---

# 4.1 scan 단계 (scanner.py)

scan은 Smart Folder와 가장 직접적으로 연결되는 단계이다.

### scan의 책임

* Smart Folder 내부 파일 탐색
* recursive 여부 적용
* 파일 확장자 검사
* 정책 위반 파일 제외
* 파일별 metadata 생성

### 출력 예시

found_files.csv:

```
path, size, modified_at, hash, allowed
/docs/projectA/report.md, 12034, ..., true
/docs/projectA/secret.pdf, 2000, ..., false
```

### Smart Folder 통합 규칙

✔ SmartFolderContext.allowed_types로 filtering
✔ deny_types 파일은 allowed=false로 표시
✔ extractor는 allowed=true 파일만 처리

---

# 4.2 extract 단계 (extractor.py)

extract 단계에서는 텍스트 추출 및 정제 작업 수행.

### Smart Folder 연동

* 파일 접근 시 AccessControl.check_access(path) 필수
* 조건부 masking enabled일 경우 내부에서 mask 적용
* 파일 전처리 규칙(policy.masking) 자동 적용

### 출력

corpus.parquet
구조:

| file | chunk | text | masked | metadata |

---

# 4.3 embed 단계 (embedder.py)

embed 단계는 semantic search를 가능하게 하는 핵심 단계.

### Smart Folder 통합

* allowed_types에 해당하지 않는 파일 chunk는 embedding 생략
  -파일 크기가 max_file_size_mb 초과면 skip
* drift detector가 특정 파일만 재-임베딩하도록 제한

### drift 기반 증분 임베딩

```
if hash_changed(file):
    re-embed(file.chunks)
```

---

# 4.4 train 단계 (trainer.py)

train의 목표:

* topic_model.joblib 생성
* vocabulary 및 semantic map 생성

### Smart Folder 영향

* Smart Folder policy가 주요 source 파일을 결정
* 허용되지 않은 파일은 topic 학습 데이터에서 제외
* masking enabled 상태라면 학습 텍스트도 masking 적용 (privacy-preserving topic model)

### 출력물

```
topic_model.joblib
corpus_metadata.json
```

---

# 4.5 watch 단계 (watcher.py)

watch는 Smart Folder + drift_detector의 총합 기능을 다룬다.

### watch 기능

* Smart Folder 내부 파일 변경 실시간 감시
* rename, delete, modify → 모두 감지
* drift detector로 변경된 파일만 처리
* embed/train을 증분 방식으로 수행

### Smart Folder와의 결합

* 정책 변경 시 watch는 즉시 재-scan 실행
* deny_types 추가 시 해당 파일 즉시 제외
* allowed_types 변경 시 재-index 필요

---

# 5. Pipeline Error Rules

| 에러                   | 원인                  | 처리                 |
| -------------------- | ------------------- | ------------------ |
| AccessDeniedError    | 폴더 외 파일 접근          | 즉시 중단              |
| PolicyViolationError | deny_types 파일 처리 시도 | 스킵 후 로그            |
| ExtractionError      | 텍스트 추출 실패           | fallback extractor |
| EmbeddingError       | 모델 로딩 실패            | retry 1회           |
| DriftDetected        | 파일 내용 변경            | 증분 업데이트 수행         |
| CorruptedIndexError  | cache mismatch      | 재생성                |

---

# 6. Pipeline ↔ Agent 연결 구조

Meeting Agent와 Knowledge Agent는 pipeline 산출물을 직접 사용한다:

```
Meeting Agent → normalized STT + summarizer  
Knowledge Agent → corpus.parquet + embeddings + topic model  
Conversation Engine → retriever, cache
```

Smart Folder 정책은 이 과정 모두에서 강제된다.

---

# 7. Smart Folder Context Injection Spec

Pipeline은 SmartFolderContext를 다음 단계마다 주입한다:

| 단계      | 전달되는 내용                        |
| ------- | ------------------------------ |
| scan    | root_path, allowed_types       |
| extract | masking rules, deny_types      |
| embed   | allowed_types, size_limit      |
| train   | masking rules, allowed_types   |
| watch   | drift rules, recursive options |

---

# 8. Developer Constraints

✔ Pipeline 내부에서 절대로 Smart Folder 외 경로 접근 금지
✔ 파일 접근 시 AccessControl.check_access() 필수
✔ train은 masking 적용 여부를 명시적으로 읽어야 함
✔ drift detector는 Smart Folder 정책 변경까지 감시해야 함
✔ 캐시 갱신은 atomic rename 방식만 사용

PR에서 이 규칙 위반 시 즉시 reject해야 한다.
